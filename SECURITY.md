# Security Policy

## Private vulnerability reporting

This repository curates an educational power-analysis resource directory. If you find a
security issue in repository-owned files, use GitHub's **Security** tab and
the private **Report a vulnerability** option, if available.

If private reporting is unavailable, open a
[security contact request](https://github.com/mohammadrezwankhan/awesome-power-analysis/issues/new)
without including passwords, credentials, exploit details, personal data,
private URLs, or sensitive logs. Ask for a private contact channel first,
then provide the technical evidence privately.

Do not publish a suspected vulnerability in a public issue or pull request.

## Scope and support

No supported-version matrix, security response-time guarantee, or operational
safety certification is claimed. A useful private report includes a commit
or release identifier, affected file, reproduction conditions, and potential
impact. Third-party power-system analysis tools, scripts, models, or datasets are not maintained or security-audited
by this repository; follow the upstream project's vulnerability policy.

## Coordinated disclosure

Maintainers can assess and coordinate remediation or disclosure after the
report is received. Do not disclose sensitive technical details publicly
until an appropriate private reporting and remediation process is established.
